The Security Maintainer owns private vulnerability intake, initial triage, severity and affected-version analysis,
remediation coordination, disclosure timing, advisory publication, and requests for a CVE when a verified issue is
eligible. The role also reviews changes to the security policy, private-report checklist, CODEOWNERS rules, release
validation, authentication and authorization boundaries, MCP execution boundaries, and sandbox enforcement.

This appointment is a public governance record. It is **not a claim of an existing CVE or GHSA**, a vulnerability
discovery, third-party adoption, or external recognition. Advisory credits must be based on documented work on a real
report, and a CVE identifier may be issued only through the applicable CVE Numbering Authority process.

## Change control

Changes to this file require the project owner's approval and a review by the current Security Maintainer. If the
role changes hands, preserve the prior appointment in Git history and update `SECURITY.md`, `.github/CODEOWNERS`, and
the repository-host security settings in the same release.
